## Найденные и исправленные баги (каждый с регресс-тестом)

1. `signer.key_from_hex` — падал на коротких hex-ключах (не падировал до
   32 байт). Вектор: ключ 0x01 → адрес 0x7e5f...5bdf.
2. `analytics.add_event` — дедуп не истекал в течение суток: ISO-'T'+tz
   строки не сравниваются с sqlite datetime('now'). Фикс: запись в
   sqlite-формате + сравнение через julianday() (переваривает и legacy-
   строки в прод-базе). 
3. `analytics.prune_events` — арифметика `id <= MAX-keep` переудаляла при
   дырках в id. Фикс: NOT IN (последние N по id).
4. `server.market_ta` — краш на идеально плоских свечах (нулевой
   боллинджер → pct_b=None → format error). Реальный кейс: стейбл-пары.
5. `detectors.equity_jumps` — утечка sqlite-соединения при исключении
   в середине батча. Фикс: try/finally.
6. `api.historical_pnl` — **граничные дубли при пагинации**: фильтр
   createdBeforeOrAt инклюзивен, каждая следующая страница повторяет
   граничную строку → задвоения в истории PnL. Поймано ЖИВЫМ тестом
   (монотонность/уникальность на реальном аккаунте). Фикс: строгий
   `< cursor` + защита от зацикливания (курсор только убывает + лимит 30
   страниц). Найдено попутно: на неотсортированных данных цикл мог
   зависнуть — добавлена защита.
7. `server.market_detail`/`suggest_stops` — невалидный тикер возвращался
   как успешный результат-словарь вместо isError (нарушение семантики
   MCP-спеки: модель не может самокорректироваться). Фикс: ValueError →
   isError-результат. Проверено онлайн-тестом (ToolError, не protocol error).

## Остаточные риски (принятые, задокументированные)

1. EIP-712 подпись не сверена с официальным клиентом (golden-вектор
   защищает от регрессий; кросс-валидация — тестнет-майлстоун, реальные
   деньги не под угрозе до подачи ордеров).
2. Фармер-эвристика не откалибрована (0 флагов; нужна эталонная метка).
3. Детекторы OI/фандинга — пороги из практики; бэктест ложных
   срабатываний по истории не гонялся (только каскады: 47 сигнатур/7д).
4. `discover`/лидерборд: equity-макс субаккаунт может отличаться от
   субаккаунта 0 в граничных случаях (сейчас обрабатывается корректно).
5. Плоский ряд → RSI=100 по нашей конвенции (задокументировано в тесте).
